# Plan - Shazam Song Recommendations based on Loaded Deck (27_06_2026-23_38)

We will update the track recommendation system to base recommendations on the song loaded in the active deck (even if not playing), support local files, and ensure the Shazam API successfully recognizes the track by serving it via a public stream proxy from local cache.

## Proposed Changes

### 1. Active Track Selection
Modify `src/App.tsx`:
- Update `activeTrack` logic to determine the active/focused track based on loaded tracks in decks A and B, using play state first, then the crossfader position, and falling back to whichever deck has a track loaded.

### 2. Auto-fetch and Source Display in Track Library
Modify `src/components/TrackLibrary.tsx`:
- Trigger recommendations reload when the active track changes.
- Add `source` state to `RecommendationsTabContent` to display whether recommendations came from Shazam or YouTube.

### 3. Audio Caching and Stream Proxy for Shazam
Modify `backend/proxy.js`:
- Refactor streaming and caching into a helper function `ensureAudioCached(videoId)`.
- In the `/api/recommend` route:
  - If the loaded track is a local track (prefix `local-`) or has no trackId but has a search query `q`, search YouTube first to resolve it to a video ID.
  - If we have a video ID, ensure the audio is downloaded and cached locally.
  - Construct a public stream URL of our server pointing to `/api/stream?videoId=${videoId}` using the request headers (`x-forwarded-host`/`host` and `x-forwarded-proto`/`protocol`).
  - Pass this public stream URL to the Shazam Song Recognition API.
  - If Shazam recognizes the track, retrieve related tracks, resolve them to YouTube video IDs, and return them with `source: 'shazam'`.
  - Otherwise, gracefully fall back to searching YouTube for `${q} music` or generic genre hits with `source: 'youtube'`.
